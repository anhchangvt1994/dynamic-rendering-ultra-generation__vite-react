# Mini-game v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Combo exp, daily quests with streak, effects and a gift chest for the card-flip mini game; mini-game badges switched off; regression tests for the 4 trainer-XP triggers.

**Architecture:** New migrations redefine `minigame_rules`, `minigame_flip`, `minigame_settle`, `minigame_finish` (unchanged body, kept), `minigame_status` and the 4 XP trigger functions, and add `minigame_quests` + RPCs. Pure rules live in `.mjs` modules with parity tests against the SQL. React gets four small components and two CSS files.

**Tech Stack:** Postgres/plpgsql + pgTAP (`supabase/tests/database`), `node --test` on `.mjs`, React 18 + styled-components, puppeteer QA in `.superpowers/qa`.

**Spec:** `docs/superpowers/specs/2026-11-11-minigame-v2-design.md`

## Global Constraints

- All RPCs: `security definer set search_path = ''`; internal ones `revoke execute … from public, anon, authenticated`; only `minigame_status`, `minigame_start`, `minigame_flip`, `minigame_finish`, `minigame_quest_claim` granted to `authenticated`.
- Lock order everywhere: Pokémon → care → bag → trainer → quests. Settle must not touch `trainer_profiles` before it writes `bag`.
- Ruling: Vietnamese UI copy; no sound; vibration only light (`navigator.vibrate`, guarded); honour `prefers-reduced-motion`.
- Day = UTC date (`(now() at time zone 'utc')::date`).
- Combo: `COMBO_STEP 0.02`, `COMBO_MAX 0.10`; `combo = min(COMBO_MAX, COMBO_STEP × (len − 1))` when won and `len ≥ 2`, else 0. Win exp = `round(base × (1 + speed + combo))`.
- Quest slots 3, distinct kinds; streak gift at 7 days then streak 0.
- Never commit `server/dist`; the user's uncommitted files stay uncommitted (`git add` only the paths named). Commits end with `Co-Authored-By: Claude Code <noreply@anthropic.com>`. Do not push.
- Test commands: pgTAP `supabase test db` (needs the local stack, container `supabase_db_pokedex`); JS `find src/pages/MiniGamePage -name '*.test.mjs' | xargs node --test`. Known flaky pre-existing reds: kitchen 4, build_items 22.
- Before browser QA: clear caches (`node .vps-lab/tmp/clear-cache.cjs`) and restart the dev server.

## Rulings made while planning (spec was silent or ambiguous)

- Quest catalog values (goal / XP): `quiz_win` 2 / 8, `cook` 1 / 6, `care` 3 / 6, `evolve` 1 / 15, `play` 2 / 5, `win` 1 / 8, `flawless` 1 / 12. Slots are the first 3 kinds by `md5(user || day || kind)`.
- Quest gift = `quiz_chest(1, 0, CHEST_SURE_W, CHEST_REST_W)` rolled once and stored in `minigame_quests.gift` (replay returns the stored one; no seed needed). Streak gift = `quiz_chest(2, 1, …)`.
- "Log" for combo: `minigame_flip` keeps `progress.run` (current chain) and `progress.best` (longest); settle reads `best` (missing → 0, so open rounds from before the upgrade settle with no combo).
- Badges: `trainer_badges`, `trainer_award_badges`, `trainer_set_avatar` stay (gym later). Settle/status stop awarding or returning badges, and settle's direct `flawless` insert is removed. Consequence: avatar `sage` (needs badge `flawless`) is no longer reachable. **Open item for the user**; this plan does not change avatars.
- Settle's early `trainer_grant_xp(user, 0)` takes the trainer lock before `bag`; kitchen takes `bag` then trainer: a deadlock. Task 3 replaces it with an unlocked read.

## Review Focus

- Concurrent `minigame_quest_claim` of the same slot twice: one gift, same receipt twice.
- `quest_bump` must never raise or block the original action (quiz, cook, care, evolve) — also with no profile and with no quest rows.
- Claim spanning midnight UTC: row of yesterday still claimable; streak uses claim day.
- Streak 7 → gift + reset to 0; next day goes to 1, not 8.
- Rounds open at deploy (no `best` in progress) still settle.
- Settle vs kitchen cook, quiz answer, care action, quest claim in parallel: no 40P01.
